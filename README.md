# homebrew-tap

kanywst's Homebrew tap. Hosts the formulae and casks for CLI and TUI tools published from this account.

Every file here is generated by an upstream release pipeline and committed from there, never edited by hand: [GoReleaser](https://goreleaser.com/) for the Go tools, [cargo-dist](https://opensource.axo.dev/cargo-dist/) for the Rust ones (`wimsey`, `wtfi2`).

What each upstream release actually ships:

| Tool | Platforms | SBOM | Signature |
| ---- | --------- | ---- | --------- |
| `rapg` | macOS, Linux, Windows (all x86_64 + arm64, Windows x86_64 only) | SPDX 2.3, one per archive | `checksums.txt.sigstore.json` |
| `y509`, `brtc`, `spiffe-compliance-checker`, `mcp-opa-authz` | macOS, Linux (x86_64 + arm64) | SPDX 2.3, one per archive | `<name>-<version>-checksums.txt.sigstore.json` |
| `wimsey` | macOS, Linux (x86_64 + arm64) | SPDX 2.3, one per release | one `.sigstore.json` per artifact |
| `wtfi2` | macOS only (x86_64 + arm64) | CycloneDX XML (`wtfi2.cdx.xml`) | none, `.sha256` files only |
| `approval-hub` | macOS, Linux (x86_64 + arm64) | none | none (repo archived at v0.0.1) |

SBOMs on the GoReleaser side come from [`syft`](https://github.com/anchore/syft), whose default output is SPDX, not CycloneDX. Signatures are keyless [Sigstore `cosign`](https://www.sigstore.dev/) over the checksum file, via GitHub OIDC. cosign 3 replaced the `.sig` + `.pem` pair with a single `.sigstore.json` bundle, so verification takes `--bundle`.

## Usage

```bash
brew tap kanywst/tap

# Formula
brew install kanywst/tap/spiffe-compliance-checker

# Cask
brew install --cask kanywst/tap/y509
```

## Verifying a release

Every tool in the table above except `wtfi2` and `approval-hub` publishes a checksum file plus a keyless `cosign` signature over it. Verifying the signature and then the digest chains trust from the workflow identity down to the binary.

`rapg` names the file plainly:

```bash
gh release download v0.3.3 -R kanywst/rapg -p 'checksums.txt*'

cosign verify-blob \
  --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github.com/kanywst/rapg/' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  checksums.txt
```

The others prefix it with name and version:

```bash
TAG=v1.2.0
REPO=y509
gh release download "$TAG" -R "kanywst/$REPO" -p '*-checksums.txt*'

cosign verify-blob \
  --bundle "${REPO}-${TAG#v}-checksums.txt.sigstore.json" \
  --certificate-identity-regexp "^https://github.com/kanywst/${REPO}/" \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  "${REPO}-${TAG#v}-checksums.txt"
```

Then check the archive you downloaded against that file with `shasum -a 256 -c`.

## How things land here

Each upstream repo's release workflow runs on `v*` tags and commits the generated file to this repo using a `HOMEBREW_TAP_GITHUB_TOKEN` secret, a fine-grained PAT scoped to `contents: write` on this repository only. The Go tools do it through GoReleaser; `wimsey` and `wtfi2` do it through cargo-dist, which generates its formula the same way.

Whether a tool lands in `Formula/` or `Casks/` is decided by the GoReleaser block the upstream repo uses: `brews` writes a formula, `homebrew_casks` writes a cask. It is not a CLI/GUI distinction. Everything published here is a terminal tool. GoReleaser deprecated `brews` in v2.10 and removed it in v2.16, so tools still on `brews` will move to `Casks/` as they migrate.
